* การเรียกฟังก์ชันซ้ำแบบไม่สิ้นสุดใน VM — ตัวนับ `fuel` ใน VM ลดเฉพาะตอนเข้าลูป `while` แต่ไม่ได้ลดเมื่อเรียกฟังก์ชัน จึงมีความเสี่ยงที่โปรแกรมเรียกตัวเองซ้ำจนใช้ทรัพยากรมากเกินไป

* มีโค้ดระดับบนสุดพร้อมกับ `main()` — ทั้ง VM และ JIT เลือกใช้โค้ดระดับบนสุดเป็นจุดเริ่มต้นก่อน `main()` ทำให้ `main()` อาจไม่ถูกรัน ทั้งที่ประกาศไว้

* Parser ยังไม่มีชุดทดสอบเฉพาะ — ในรายการไฟล์ที่ตรวจพบ ยังไม่พบไฟล์ทดสอบ Parser โดยตรง

### 2\. บัค — VM ไม่ตรวจจำนวน Parameter ของ main

ความสำคัญปานกลาง

ไฟล์ `src/lib/lang/vm.ts` บรรทัด 238–240

VM สร้าง Local Variables ของฟังก์ชันเริ่มต้นเป็น `0` ทั้งหมด โดยไม่ตรวจว่า `main` ต้องรับ Parameter หรือไม่

แต่ JIT ตรวจจำนวน Argument ด้วย `arguments.length`

ผลที่อาจเกิดขึ้นคือโค้ดที่ผิดจำนวน Argument ถูก VM ยอมให้ทำงาน แต่ JIT ปฏิเสธ

### ประเด็นเพิ่มเติมที่ควรตรวจ

* `compileVm()` และ `compileJit()` เลือก `<top>` ก่อน `main` หากมีทั้งสองอย่าง ทำให้ `main` ไม่ทำงาน ต้องกำหนดพฤติกรรมที่ต้องการให้ชัดเจน

* `freshName()` มีกรณีชื่อไฟล์ชนกันตั้งแต่ `-2` ถึง `-999` แล้วคืนชื่อ `-x` โดยไม่ได้ตรวจว่าชื่อ `-x` มีอยู่แล้วหรือไม่ อาจเขียนทับไฟล์เดิมในระบบจำลอง
