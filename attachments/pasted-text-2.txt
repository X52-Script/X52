### 2\. บัคที่ยืนยันได้ในฉบับใหม่

### บัคที่ 1 — main ไม่ทำงานเมื่อมีการเรียกอยู่ในเงื่อนไขที่ไม่เป็นจริง

สำคัญสูง

ไฟล์ `src/lib/lang/ast.ts` บรรทัด 54–77

ปัญหาอยู่ที่ `prepareEntry()` ตรวจว่ามีคำว่าเรียก `main()` อยู่ในโค้ดหรือไม่ โดยไม่ได้ตรวจว่าคำสั่งนั้นจะถูกรันจริงหรือเปล่า

ตัวอย่าง X52:

```x52
if 0 {
    main()
}

fn main() {
    print(99)
}
```

ผลที่ผมทดลองได้:

```text
ok: true
output: ""
```

X52+ ก็แสดงอาการเดียวกัน

นี่เป็นบัคจริง เพราะแม้เงื่อนไขไม่ทำงาน ระบบก็เข้าใจว่าเรียก `main()` ไปแล้ว จึงไม่เพิ่มการเรียก `main()` ตามปกติ

### บัคที่ 2 — X52 กับ X52+ หารด้วยศูนย์ไม่เหมือนกัน

สำคัญปานกลาง

ไฟล์:

* `src/lib/lang/vm.ts` บรรทัด 285–286

* `src/lib/lang/jit.ts` บรรทัด 34–37

ผลทดสอบ:

| โปรแกรม     | ผลลัพธ์                   |
| ----------- | ------------------------- |
| X52: 1 / 0  | Error หารด้วยศูนย์        |
| X52+: 1 / 0 | สำเร็จ แต่ได้ ไม่ใช่จำนวน |

สาเหตุคือ VM ตรวจหารด้วยศูนย์ แต่ JIT ใช้การหารของ JavaScript โดยตรง

หากต้องการให้ทั้งสองภาษาใช้ Semantics เดียวกัน ต้องแก้ให้พฤติกรรมตรงกัน

### บัคที่ 3 — GitHub Actions ยังไม่ได้สร้างหรือเขียนไฟล์จริง

สำคัญสูง

ไฟล์:

* `.github/workflows/create.yml`

* `.github/workflows/write.yml`

ฉบับใหม่นี้มี `workflow_dispatch` และ `jobs` แล้ว ถือว่าโครงสร้าง Workflow ดีขึ้นจากเดิม

แต่เนื้อหาในขั้นตอนทำงานยังเป็นเพียง:

```bash
echo "create does not write file contents"
echo "path=..."
echo "conflict=..."
```

ดังนั้น:

* `create.yml` ยังไม่ได้สร้างไฟล์

* `write.yml` ยังไม่ได้เขียนเนื้อหา

* ไม่มีขั้นตอน checkout Repository

* ไม่มีการบันทึกการเปลี่ยนแปลงกลับ Repository

อีกเรื่องคือมีการแทรก `${{ inputs.path }}` ลงในคำสั่ง Shell โดยตรง ควรเปลี่ยนไปส่งผ่าน `env:` และอ้างตัวแปรใน Shell อย่างปลอดภัย เพื่อป้องกัน Shell Injection จาก Input

### บัคที่ 4 — write สามารถสร้างไฟล์ใหม่ได้เมื่อเลือก Overwrite

สำคัญปานกลาง

ไฟล์ `src/lib/workflow/engine.ts` บรรทัด 208–216

ข้อกำหนดของระบบบอกว่า `write` ต้องเขียนไฟล์ที่มีอยู่แล้วเท่านั้น ห้ามสร้างไฟล์ใหม่

แต่เมื่อเลือกโหมด `overwrite` และไม่มีไฟล์เดิม ระบบกลับใช้ `upsert()` สร้างไฟล์ใหม่ขึ้นมา

จุดนี้ยังขัดกับความหมายของ `Write without create` และมี Self-check ที่ยืนยันพฤติกรรมดังกล่าวอยู่แล้วใน `src/lib/lang/selfcheck.ts` บรรทัด 59–64 จึงควรทบทวนทั้ง Logic และ Test ให้ตรงกับข้อกำหนด

### บัคที่ 5 — ระบบตั้งชื่อไฟล์ยังมีขอบเขตจำกัด

ไฟล์ `src/lib/workflow/engine.ts` บรรทัด 132–149

ค้นหาชื่อสำรองถึง `-100000` เท่านั้น หากชื่อนั้นมีอยู่แล้วจะโยน Error แม้ชื่อ `-100001` จะยังว่างอยู่

เป็นปัญหาขอบเขตที่มีโอกาสเกิดน้อย แต่ควรแก้ให้ค้นหาชื่อที่ว่างได้จริงโดยไม่กำหนดเพดานที่ทำให้หยุดก่อนเวลา
